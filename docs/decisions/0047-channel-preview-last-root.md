# 0047 — Превью чата в сайдбаре: последнее сообщение канала, а не треда

Дата: 2026-10-22
Статус: принято, реализовано

## Контекст

Фича-репорт: под названием чата в списке чатов показывается «последнее
сообщение». Если у корневого сообщения есть тред, превью брало последний
**ответ треда** — пользователь хочет видеть последнее сообщение самого
канала всегда.

Probe живого сервера (7.8.0 Okko-патчи): `GET /channels/{id}/posts`
отдаёт корни и ответы вперемешку, параметр `collapsed_threads` порядок и
состав страницы не меняет. Значит, «последнее сообщение канала» = последний
**корневой** пост — и его надо искать на клиенте.

## Решение

1. **Realtime** (`handlePosted`): превью обновляют только корневые посты
   (`root_id == nil`). Ответ треда не всплывает в список чатов; штамп
   превью (`channelPreviewStamp`) хранит id корня, поэтому и правка, и
   удаление ответа превью не задевают. Удаление preview-корня чистит
   превью как раньше (backfill заполнит заново).
2. **Backfill** (`backfillSidebarPreviews`): вместо `.latest(perPage: 1)`
   читается страница до `sidebarPreviewPageSize = 60` постов, из неё берётся
   первый корень; если страница — сплошные ответы, одна дополнительная
   страница (`.before`, всего ≤2 запросов на канал за сессию). Превью —
   косметика, дальше двух страниц не ищем.
3. **Гонка с realtime**: заполненное превью не перезаписывается более
   старым корнем (сравнение со свежим `lastRootPostAt` из директории,
   локальный снапшот канала для сравнения не используется).

Сортировка чатов не менялась: канал с активным тредом по-прежнему
поднимается по `lastPostAt` — пользователь просил только про текст превью.

## Последствия

- Ни одного лишнего запроса: backfill остался одним task'ом на канал
  (плюс редкая вторая страница), realtime-правка — локальная.
- Тесты: `SidebarPreviewTests` — backfill берёт корень, а не ответ;
  ответ не перезаписывает превью, новый корень — обновляет; поиск
  корня продолжается за пределами страницы из одних ответов.
