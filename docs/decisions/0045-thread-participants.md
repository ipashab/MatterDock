# 0045 — Аватарки участников треда у чипа «N ответов»

Дата: 2026-10-22
Статус: принято, реализовано

## Контекст

Фича-репорт: в официальном клиенте рядом с чипом «N ответа» под корнем треда
рисуются 1–4 аватарки пользователей, оставивших ответы. Наш клиент показывал
только текст чипа.

Разбор провода (чат chat.okko.team, сервер 7.8.0 после Okko-патчей) показал,
что участники приходят **на верхнем уровне поста**: `participants` у корневого
сообщения CRT-страницы канала (запрос с `collapsedThreads=true`). Это массив
объектов-пользователей, у которых заполнен только `id` (`username`, `first_name`
и прочее — пустые). Эндпоинтов `/channels/{id}/threads` и `thread_stats` на
сервере нет; `props` и одиничный `GET /posts/{id}` их не несут. Подтверждено
реверсом бандла официального вебклиента: селектор читает `thread.participants`,
**reverse** и срез; правило показа — больше 4 участников → 3 аватарки + бабл
«+N», иначе все (максимум 4).

## Решение

1. **Wire** (`PostWire`): верхний `participants` → `[UserID]`. Битые элементы
   пропускаются (`LossyArray<ThreadParticipantWire>`, идентификатор строго
   валидируется), дубликаты схлопываются, хранение ограничено
   `maximumThreadParticipants = 64`. Отсутствие поля — `nil` («не прислали»),
   пустой массив — `[]`.
2. **Модель**: `Post.threadParticipantIDs: [UserID]?` — опционально, как
   `quotedPost`: посты старого кэш-формата декодируются без потерь.
3. **Билдер**: `PostPresentation.threadParticipants: [AuthorPresentation]` —
   хвост списка свежими первыми (порядок официальный: свежий ближе к тексту),
   уже срезанный до показа; `threadParticipantsOverflow` — остаток для бабла
   «+N». Профили — обычный резолв по директории; незнакомые уезжают в
   `missingUsers` и подкачиваются существующим механизмом.
4. **Layout**: круги 16 pt с шагом 12 (наложение), через 8 pt после текста
   чипа, вертикально по центру строки чипа — высота ряда не растёт. Не влезают
   в колонку — не показываем. Работает в обоих режимах (пузырь и flat).
5. **Ячейка**: пул `AvatarView` (≤4, растёт по мере надобности), картинки —
   через общий конвейер (`TimelineImageRequest.avatar`), клик открывает тред,
   как чип; reset/reuse/lifecycle — по образцу author-аватара. Бабл остатка —
   круг с «+N»; a11y-подпись — «и ещё N участников» (локализована).
6. **Merge** (`PostStore.upsert`): тот же updateAt — серверная страница
   доносит участников кэш-сиду старого формата (backfill, как у цитаты в
   0044). Копия новее без списка (since-окно, тред-запрос, realtime) не
   теряет уже известное.
7. **Realtime**: `updateThreadRoot` добавляет автора свежего ответа в конец
   списка (дедуп, лимит) — аватарки у чипа растут вживую, как в официальном
   клиенте; страница канала при следующем заходе выравнивает список сервером.

## Следствия

- Один дополнительный запрос не появляется: участники едут в уже запрашиваемой
  CRT-странице канала; realtime — вложением в существующие события.
- Память: ≤64 id на корень треда с ответами; аватарки — ≤16 pt картинок через
  общий LRU-конвейер, без отдельных закупок.
- Удалённый ответ не убирает автора из участников: сервер ведёт список так же
  (участник ≠ количество ответов).

## Тесты

Wire (лейни/дедуп/лимит/nil-vs-[]), билдер (порядок, срез, overflow,
missing-users), layout (кадры за чипом, шаг, высота ряда, оба режима, границы
колонки), store (tie-backfill и сохранение при апдейте без списка), realtime
(живой ответ добавляет участника, дедуп). Red-check на всех четырёх слоях.
