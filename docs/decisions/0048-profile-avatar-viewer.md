# 0048 — Просмотр и сохранение аватарки из профиля

Дата: 2026-10-22
Статус: принято, реализовано

## Контекст

Фича-репорт: в карточке профиля («О канале», поповер автора, настройки)
хочется кликнуть по аватарке и посмотреть её крупно, а правым кликом —
сохранить.

## Решение

1. **Вьюер**: аватар открывается в общем `MediaViewerController` (та же
   machinery, что у картинок вложений: зум, копирование, Esc/клик —
   закрыть). Картинка грузится через обычный конвейер
   `profileImage(userID, revision, maxPixelSize)` с полным экраном
   разложений; лиз вьюера отпускается при закрытии. Контроллер держит
   `ProfileAvatarMedia` (static), потому что overlay хранит его weak, а
   карточка живёт в поповере, а вьюер — в главном окне (`NSApp.keyWindow`,
   как у файлового поиска).
2. **Сохранение**: контекстное меню аватара «Сохранить аватар…» и кнопка
   сохранения вьюера пишут PNG уже показанной (полностью загруженной)
   картинки; если лиза нет — отдельная загрузка в максимальном бюджете
   `maximumImagePixelDimension`. Явное действие пользователя: `NSSavePanel`
   → запись по выбранному пути, никаких тихих записей (SPEC §7).
3. **Где включено** (`opensViewer`): карточка профиля (поповер автора,
   «О канале»), аватар собеседника в «О канале», строки участников канала,
   свой аватар в настройках. Не включено там, где аватар — часть строки
   (сайдбар, поиск).
4. **Имя файла**: имя человека минус управляющие символы, `/ \ :` и
   лишние пробелы; слова через дефис, `имя.png`.
5. Кнопка сохранения вьюера для аватара подписана «Сохранить аватар…»
   (a11y/подсказка), у вложений — прежняя.

## Последствия

- Один дополнительный запрос — только при явном открытии аватара
  (профильная картинка и так кешируется пайплайном по (user, revision,
  размер)).
- Тесты: `avatarViewerLoadsAndReleasesTheProfilePicture` — вьюер
  открывается из карточки, лиз грузится и отпускается, генерация имени
  файла чистит пути.
