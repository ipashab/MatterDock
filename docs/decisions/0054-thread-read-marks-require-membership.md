# 0054 — Read-метки тредов только при существующем членстве: сервер строит
# подписку из метки

Дата: 2026-10-22. Статус: принято.

## Контекст

Репорт пользователя: треды, на которые он не подписывался, приходят с меткой
«отслеживается» и шлют уведомления; подозрение — клиент сам подписывается на
всё. Разбор исходников mattermost-server v7.8 подтвердил подозрение с точностью
до вызова.

Сервер 7.8 превращает read-метку одного треда в подписку. `PUT
/users/{uid}/teams/{t}/threads/{id}/read/{ts}` → `UpdateThreadReadForUser`
(app/user.go) вызывает `ThreadStore.MaintainMembership` с
`ThreadMembershipOpts{Following: true, UpdateFollowing: true}`:

- строки членства нет — она **создаётся сразу с Following=true** (фантомная
  подписка);
- строка есть — `Following` **форсируется в true**, даже если пользователь
  только что отписался (Unfollow в 7.8 строку удаляет, так что подписка
  «воскресает» из первой же метки).

MatterMac до этого решения ставил метку любому треду, чья панель открыта на
живом крае ≥600 мс (`evaluateThreadReadState`) — без проверки членства. Достаточно
кликнуть «N ответов», чтобы молча подписаться навсегда; дальше тред попадает в
Inbox (SQL списка фильтрует `Following = true`) и каждое событие треда уходит в
`followers` — то есть уведомления о нём корректны с точки зрения сервера, но
само членство — фантом.

Официальный веб-клиент мину обходит: `thread_viewer.tsx markThreadRead()` ставит
метку **только если `userThread != null`** (членство уже есть) и есть что
прочитать.

Командная метка сервера безопасна: `PUT .../threads/read` →
`MarkAllAsReadByTeam` — чистый UPDATE без создания членств и смены Following.

## Решение

- `evaluateThreadReadState` (`Session/ServerSession+Read.swift`) перед меткой
  запрашивает членство (`GET /users/{me}/teams/{t}/threads/{root}`, 404 → nil).
  Метка ставится **только при существующем членстве**; иначе — позиция
  фиксируется локально (без кругового опроса), серверу не отправляется ничего.
  Без членства у сервера нет и непрочитанных, метить нечего.
- `userThread` клиента уже мапит 404 в nil; `isFollowingThread` — «строка есть ⇒
  подписан» — для 7.8 точен (Unfollow удаляет строку). Семантика оставлена.
- Командная `markThreadRead(nil)` («все прочитано») и явные метки из UI не
  тронуты: первые — UPDATE на сервере, вторые — доля пользователя.

## Последствия

- Открытие/просмотр треда больше не подписывает и не воскрешает подписку после
  явного Unfollow. Фантомных членов `followers` не появляется — вместе с
  решением 0051 это закрывает и поток уведомлений из чужих тредов в диалогах.
- Цена — один GET членства на сработавшую метку; экономика та же, что у
  веб-клиента (его `getThread` на открытии вьюера).
- Уже созданные фантомные подписки живут на сервере; пользователь убирает их
  штатным Unfollow в Inbox. Автоматической чистки нет и не будет: отличить
  фантом от осознанной подписки клиент не может.
- Проверено на исходниках mattermost-server v7.8.0 (`app/user.go`,
  `store/sqlstore/thread_store.go`) и mattermost-webapp v7.8.0
  (`threading/thread_viewer/thread_viewer.tsx`, `threading/global_threads/*`).
