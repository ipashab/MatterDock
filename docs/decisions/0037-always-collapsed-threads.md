# 0037 — Свёрнутые треды всегда включены (политика форка MatterDock)

Дата: 2026-10-21. Статус: принято.

## Контекст

Upstream включает Collapsed Reply Threads (CRT) только когда сервер сконфигурирован
`CollapsedThreads: default_on/always_on` и личный preference `collapsed_reply_threads`
включён. На серверах с `disabled`/выключенным preference ответы в тредах рендерятся
в основном таймлайне канала с маркером «Replied to a thread». Пользователь форка
хочет поведение официального клиента всегда: в канале — только корневые сообщения
со счётчиком «N replies», ответы — только в панели обсуждения справа.

## Решение

- `ServerSession.collapsedThreadsActive` безусловно возвращает `true`; конфигурация
  сервера и preference игнорируются.
- Тумблер «Collapsed reply threads» в Settings удалён (имеет стабильную подпись
  «Always on (MatterDock)»; серверная настройка больше ни на что не влияет).
- `setCollapsedThreads` удалён из `ServerSession` и `SessionViewModel` (запись
  мёртвого preference).
- Заголовок панели обсуждения дополнен именем канала — как в официальном клиенте
  («Обсуждение | <канал>»); реализовано как `Thread · <канал>`.

## Последствия

- Механизм CRT (панель, счётчики ответов, фоллоу, непрочитанные треды) работает на
  любых серверах, включая старые с `disabled`.
- Реалтайм-ответы никогда не вставляются в окно канала, REST-страницы канала
  фильтруются по `rootID == nil` всегда.
- Изменение preference `collapsed_reply_threads` (в том числе из других клиентов)
  больше не перезагружает таймлайны.
- Тесты, проверявшие переключение режимов, переписаны под постоянное состояние
  (`ThreadsTests`, `NotificationPreferencesTests`).
