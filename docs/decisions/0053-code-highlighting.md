# 0053 — Подсветка синтаксиса код-блоков: минимальный лексер, системные цвета

Дата: 2026-10-22. Статус: принято.

## Контекст

Репорт пользователя: код в блоках ``` — сплошной серый, читать неудобно; в
официальном веб-клиенте есть подсветка (highlight.js). Внешних зависимостей форк
не тащит (SPEC §2), а полноценный движок подсветки ради «читать код в чате» —
overkill.

## Решение

- `CodeHighlighter` (`Rendering/CodeHighlighter.swift`) — однократный O(n)-лексер
  без внешних движков: комментарии (строчные, блочные), строки (кавычки, тройные
  кавычки, backtick, экранирование), числа, ключевые слова. Профили: python
  (+py), bash (+sh/shell/zsh), javascript (+js/ts/typescript/jsx/tsx), json, go
  (+golang), sql (+psql/postgres, без учёта регистра). Незнакомый язык или код
  без метки рендерятся одним цветом, как раньше.
- Цвета — `TimelinePalette.codeKeyword/.codeString/.codeNumber/.codeComment` на
  системных цветах (`systemRed`, `systemBlue`, `tertiaryLabelColor`): адаптация к
  тёмной теме и повышенной контрастности бесплатна, ключ кеша рендера не различает
  варианты — цвет разрешается при отрисовке.
- Интеграция — только в `renderCodeBlock`: сегменты дописываются в тот же
  `TimelineTextBlock` тем же моноширинным шрифтом, различие одно — цвет текста.
  Бюджет рендера не менялся: сегменты лишь дробят атрибут-раны внутри блока,
  общий `remaining`-лимит текста действует как раньше.

## Последствия

- Ошибка лексера не может «сломать» сообщение: свойство тестов — сегменты
  всегда восстанавливают исходный текст один в один; расхождение = баг тестов.
- Полнота подсветки принесена в жертву простоте: regex-литералы, shebang, heredoc
  и т.п. не познаются — осознанный уровень «достаточно, чтобы читать».
- Больше атрибут-ранов на блок → `renderCost` растёт, и очень тяжёлый код-блок
  попадёт под общий лимит вывода чуть раньше простого текста. Это согласовано с
  бюджетной политикой документа, отдельный предел не заводится.
