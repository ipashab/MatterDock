# 0044 — Карточка «ответ на сообщение» (props.quote_post_id)

Дата: 2026-10-22
Статус: принято, реализовано

## Контекст

Баг-репорт: ответы на конкретное сообщение в тредах рендерятся как обычные
сообщения — карточки «В ответ на …» нет.

Wire-проба живого сервера (chat.okko.team) показала два канала контекста:
1. `props.quote_post_id` и дубль `props.previewed_post` — идентификаторы
   цитируемого поста; тело сообщения чистое, без markdown-цитаты.
2. `metadata.embeds[type=quote].data.post` — **полный** вложенный процитированный
   пост (автор, текст, delete_at). Официальный клиент рисует карточку именно
   из него.

Первая реализация (фазы wire+store) читала только идентификаторы и резолвила
цитату по локальному стору. В тредовом окне это работает (тред — полная
страница, цитата в нём), но в канале процитированное сообщение часто лежит за
пределами загруженной страницы — карточка молчала. Репорт-2: «В треде — ответ
есть, в канале чата — нет».

## Решение

1. **Первичный источник — embed**: `Post.quotedPost: QuotedPost?` (вар по
   образцу `customEmojis`, без правки init) декодируется из
   `metadata.embeds(quote)`; у quote-эмбеда нет `url`, поэтому ветка декодера
   идёт до url-guard. Текст ограничен 2 KiB (`maximumQuotedMessageBytes`) —
   карточка показывает 96-символьный обрывок, полный пост не нужен.
   Сверка `post_id == post.id` — мусорные эмбеды отбрасываются.
2. **Fallback — store**: `props.quote_post_id` без embed резолвится локально
   (по-прежнему без prefetch: нет поста — нет карточки).
3. **Wire**: `PostPropsWire` декодирует `quote_post_id`/`previewed_post`
   (порядок обхода ключей у Codable не гарантирован, выбираем канонический).
   Модель: `PostProps.quotePostID: PostID?`.
4. **Билдер**: `ReplyContext` (автор из DirectoryStore + обрывок ≤96,
   `snippet(limit:)` общая с чипом треда); удалённые/системные цитаты и ссылки
   на себя — `nil`.
5. **Рендер**: в пузырном режиме карточка внутри пузыря над телом
   (полоса 3 pt + автор + обрывок, Telegram-стиль); в flat-режиме — строка над
   телом. Hug учитывает ширину карточки, высота пузыря растёт ровно на неё.
   Клик (и Return/Space при Full Keyboard Access) — прыжок к процитированной
   строке: центрирование + flash, как permalink-перелёт; поста в окне нет —
   тихий no-op (без загрузок).
6. Цвета следуют поверхности (свой/чужой пузырь/flat) — динамические системные,
   как у остального таймлайна; доступность — роль кнопки, «В ответ на …».

## Последствия

- Ответы снова читаются как ответы — визуальный контекст восстановлен.
- Захардкоженных prefetch-пилюль нет: карточка честно локальная.
- Ревизии строк учитывают `replyContext` — лейаут-кеш инвалидируется корректно.

Верификация: wire-тесты (обе алиасные клавиши, приоритет, пустые значения) с
red-check; билдер-тесты (резидентный стор, тишина при отсутствии/удалении/
self-quote, лимит сниппета); layout-тесты (карточка над телом в пузыре и flat,
рост высоты, hug); полный прогон пакета — зелёный, 0 warnings.
